Instrukcja obslugi projektu (wersja uproszczona i jednoznaczna)

Ta wersja usuwa niepotrzebne rzeczy i odpowiada konkretnie: ktory plik konfigurujesz, w jakim formacie, jakie klucze sa wymagane oraz co musi byc widoczne w Docker Desktop.

Visual Studio 2022 Docker Desktop .NET 8 SQL Server + Dapper + FluentMigrator

01. Jak czytac te instrukcje

Format kazdego kroku:

  • Akcja: co kliknac lub wpisac.
  • Widok: co powinienes zobaczyc na ekranie.
  • Znaczenie: dlaczego to jest wazne.
  • Nastepny krok: co robisz dalej.

Cel: po przejsciu calej instrukcji masz dzialajacy projekt lokalnie i w Docker Desktop, z poprawna konfiguracja sekretow i bazy.

02. Wybierz 1 wariant konfiguracji (nie oba naraz)

Zasada glowna: konfigurujesz jeden zestaw plikow zaleznie od sposobu uruchamiania.

Jak uruchamiaszKtory plik konfigurujeszCzy potrzebny .env
Visual Studio (F5 / Ctrl+F5) src/KuchniaUCygana.Web/appsettings.Development.json Nie
Docker Desktop (docker compose) .env Tak

Nie mieszaj scenariuszy: jesli testujesz przez Docker, priorytet ma konfiguracja z .env (przez zmienne srodowiskowe compose).

03. Format danych (dokladnie)

A. Format pliku appsettings.Development.json

JSON - przyklad poprawnego formatu
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=kuchniaucygana_dev.db"
  },
  "JwtSettings": {
    "SecretKey": "minimum_32_znaki_bez_spacji",
    "Issuer": "KuchniaUCygana",
    "Audience": "KuchniaUCyganaUsers",
    "ExpiryHours": 8
  }
}

B. Format pliku .env (Docker)

ENV - jedna linia = jedna zmienna
JWT_SECRET=minimum_32_znaki_bez_spacji
STRIPE_SECRET=
OPENAI_KEY=

Wymagane minimum: w praktyce na start potrzebujesz JWT_SECRET. Klucze STRIPE_SECRET i OPENAI_KEY moga pozostac puste, jesli nie uruchamiasz funkcji tych integracji.

04. Inicjalizacja w Visual Studio

3.1 Otwieranie solution i pierwszy przeglad

Akcja: dwuklik na plik KuchniaUCygana.sln w root repo.

Widok: po lewej Solution Explorer z projektami:

  • KuchniaUCygana.Web
  • KuchniaUCygana.Application
  • KuchniaUCygana.Domain
  • KuchniaUCygana.Infrastructure
  • KuchniaUCygana.Tests

Znaczenie: to jest poprawna architektura warstwowa i punkt startu pracy.

3.2 Uzupelnienie danych lokalnych (bez Dockera)

Akcja: otworz plik src/KuchniaUCygana.Web/appsettings.Development.json.

Widok: sekcje ConnectionStrings, JwtSettings, Stripe, OpenAI.

Co uzupelnic: lokalne wartosci testowe (nie produkcyjne).

Przyklad danych do wpisania
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=kuchniaucygana_dev.db"
  },
  "JwtSettings": {
    "SecretKey": "lokalny_klucz_min_32_znaki_do_testow",
    "Issuer": "KuchniaUCygana",
    "Audience": "KuchniaUCyganaUsers",
    "ExpiryHours": 8
  },
  "Stripe": { "SecretKey": "sk_test_..." },
  "OpenAI": { "ApiKey": "sk-..." }
}

Wazne: ten plik jest lokalny. Nie commituj sekretow do repo.

3.3 Pierwsze uruchomienie z Visual Studio

Akcja: ustaw startup project na KuchniaUCygana.Web, kliknij Run (lub F5).

Widok: uruchomiona aplikacja + okno Output/Debug.

Znaczenie: przy starcie odpala sie migrator i tworzy baze SQLite.

Co dzieje sie w tle: Program.cs wywoluje runner migracji, a warstwa Infrastructure konfiguruje FluentMigrator + Dapper.

05. Uruchamianie przez Docker Desktop (minimalne komendy)

5.1 Przygotowanie pliku .env

  1. W root repo skopiuj .env.example do .env.
  2. Uzupelnij minimum JWT_SECRET. Pozostale pola mozesz zostawic puste, jesli nie uzywasz tych integracji.
Plik .env (minimalny)
JWT_SECRET=min_32_znakowy_klucz
STRIPE_SECRET=
OPENAI_KEY=

5.2 Start kontenera (jedna komenda)

Uruchomienie
docker compose up --build

5.3 Co powinno pojawic sie w Docker Desktop - Containers

Akcja: otworz Docker Desktop - zakladka Containers.

Widok oczekiwany: kontener kuchnia_web ze statusem Running.

Dodatkowo: po wejsciu w kontener zobaczysz:

  • Logs - logi aplikacji (debug bledow)
  • Exec - terminal wewnatrz kontenera
  • Inspect - parametry uruchomienia

5.4 Co powinno pojawic sie w Docker Desktop - Volumes

Akcja: otworz zakladke Volumes.

Widok oczekiwany: volume sqlite_data i uploads_data.

Znaczenie: dane bazy i uploady sa trwale, nie znikaja po restarcie kontenera.

Kazdy developer ma swoja baze: kazdy ma osobne lokalne volume Dockera na swoim komputerze.

07. Scenariusze pracy (dokladnie)

Scenariusz A - "Chce tylko uruchomic aplikacje i zobaczyc czy dziala"

  1. Otworz KuchniaUCygana.sln w VS.
  2. Uzupelnij appsettings.Development.json.
  3. Uruchom startup project KuchniaUCygana.Web.
  4. Sprawdz, czy strona laduje sie w przegladarce.

Scenariusz B - "Chce uruchomic przez Docker Desktop"

  1. Utworz i uzupelnij plik .env.
  2. Uruchom docker compose up --build.
  3. W Docker Desktop sprawdz status kontenera na Running.
  4. Otworz aplikacje na http://localhost:8080.

Scenariusz C - "Nowy developer dolacza do zespolu"

  1. Klonuje repo i otwiera solution w Visual Studio.
  2. Ustawia lokalne sekrety w swoim pliku deweloperskim.
  3. Uruchamia app i sprawdza, czy migracje tworza baze.
  4. Tworzy wlasny branch feature i zaczyna prace.

08. Typowe problemy i rozwiazania

Problem: aplikacja nie startuje, blad konfiguracji JWT

Co sprawdzic: czy SecretKey ma minimum 32 znaki i jest uzupelniony w odpowiednim pliku.

Problem: brak tabel po starcie

Co sprawdzic: logi aplikacji i czy migracje sa uruchamiane przy starcie (Program.cs -> MigrationRunner).

Problem: Docker kontener sie zatrzymuje

Co zrobic: wejdz w Docker Desktop -> Containers -> kuchnia_web -> Logs i sprawdz pierwsze czerwone bledy.

Problem: nie wiem czy mam konfigurowac appsettings czy .env

Regula: Visual Studio run = appsettings.Development.json. Docker run = .env. Wybierasz jeden wariant dla konkretnego uruchomienia.
