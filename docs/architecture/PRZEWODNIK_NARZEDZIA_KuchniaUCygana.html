01. Cel dokumentu

Celem jest ujednolicenie sposobu pracy zespolu: kazdy developer ma identyczne kroki setupu, rozumie narzedzia i wie gdzie umieszczac kod, konfiguracje i dane.

Dla kogo
  • Developer .NET pracujacy w Visual Studio.
  • Osoba uruchamiajaca aplikacje przez Docker Desktop.
  • Czlonek zespolu, ktory musi skonfigurowac lokalne sekrety i baze.

04. Instalacja krok po kroku

Krok 1 - Visual Studio

  • Zainstaluj Visual Studio 2022.
  • W instalatorze zaznacz workload ASP.NET and web development.
  • Sprawdz, czy masz .NET SDK 8.x.
Weryfikacja .NET

Krok 2 - Docker Desktop

  • Zainstaluj Docker Desktop.
  • Uruchom i upewnij sie, ze status to Running.
Weryfikacja Docker
docker --version
docker compose version

Krok 3 - Klonowanie i restore

Pobranie repo
git clone <URL_REPO>
cd KuchniaUCygana
dotnet restore

05. Dane i sekrety - co uzupelnic przed uruchomieniem

A. appsettings.Development.json (uruchamianie lokalne bez Dockera)

Plik znajduje sie w src/KuchniaUCygana.Web/. Uzupelnij lokalne klucze testowe.

Przykladowe wartosci
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=kuchniaucygana_dev.db"
  },
  "JwtSettings": {
    "SecretKey": "lokalny_klucz_min_32_znaki_do_testow",
    "Issuer": "KuchniaUCygana",
    "Audience": "KuchniaUCyganaUsers",
    "ExpiryHours": 8
  },
  "Stripe": { "SecretKey": "sk_test_..." },
  "OpenAI": { "ApiKey": "sk-..." }
}

B. .env (uruchamianie przez Docker)

Skopiuj .env.example do .env i uzupelnij wartosci.

Plik .env
JWT_SECRET=min_32_znakowy_klucz
STRIPE_SECRET=sk_test_...
OPENAI_KEY=sk-...
Skad pozyskac dane: Stripe Dashboard (sekcja API keys), OpenAI Dashboard (API keys), JWT key generujesz lokalnie (losowy ciag min. 32 znaki).

06. Jak uruchamiac projekt

Tryb 1: Visual Studio / dotnet run
  1. Otworz KuchniaUCygana.sln w VS.
  2. Ustaw startup project: KuchniaUCygana.Web.
  3. Sprawdz appsettings.Development.json.
  4. Uruchom (F5 / Ctrl+F5).
Tryb 2: Docker Desktop
  1. Utworz i uzupelnij .env.
  2. W root repo uruchom docker compose up --build.
  3. Aplikacja wystartuje na porcie 8080.
Komendy szybkiego startu
# lokalnie:
dotnet run --project src/KuchniaUCygana.Web

# docker:
docker compose up --build

# zatrzymanie:
docker compose down

07. Baza danych, Dapper i FluentMigrator

Jak to dziala technicznie

  • Connection string jest pobierany z konfiguracji (appsettings/env).
  • FluentMigrator odpala migracje automatycznie przy starcie aplikacji.
  • Dapper obsluguje zapisy/odczyty danych w repozytoriach.
WarstwaOdpowiedzialnoscPrzyklad
Migracje (DDL)Tworzenie/zmiana tabel, indeksow, kluczy001_CreateUsersTable.cs
Repozytoria (DML)CRUD i zapytania danychBaseRepository.cs
RunnerUruchomienie migracji przy starcie appMigrationRunner.RunMigrations()
Tak, kazdy developer moze miec wlasna baze. Lokalnie jest osobny plik .db, a przy Dockerze oddzielny volume na maszynie developera.

08. Workflow codzienny w projekcie

  • Pracujesz na branchu feature/devX-modul.
  • Na start dnia robisz synchronizacje z develop.
  • Wrzucasz PR: feature -> develop.
  • Review robi osoba inna niz autor.
  • Do main trafia kod dopiero po przejsciu przez develop.
Codzienny zestaw komend
git checkout develop
git pull origin develop
git checkout feature/devX-modul
git merge develop

# po zmianach:
git add .
git commit -m "Opis zmian"
git push

09. Najczestsze problemy i rozwiazania

Aplikacja nie startuje, blad connection string

Sprawdz, czy uzupelniles appsettings.Development.json albo zmienne w .env. Upewnij sie, ze klucz to ConnectionStrings__DefaultConnection (Docker) lub sekcja ConnectionStrings (lokalnie).

Migracje nie tworza tabel

Sprawdz czy klasa migracji ma atrybut [Migration(nr)] i czy assembly z migracjami jest skanowane w DI.

Docker uruchamia sie, ale brak danych po restarcie

Zweryfikuj, czy volume jest podmontowany: sqlite_data:/app/data. Bez tego plik DB w kontenerze zniknie po usunieciu kontenera.
